## Reproduce

```bash
export LONGRUN_SCRATCH=<a directory outside the repo>
node tools/slice20-research/longrun/lib/build.mjs
node tools/slice20-research/longrun/lr2-symmetric/verify-lookup.mjs      # must print PASS
node tools/slice20-research/longrun/lr2-symmetric/run-shard.mjs --shard 0 --of 3 &
node tools/slice20-research/longrun/lr2-symmetric/run-shard.mjs --shard 1 --of 3 &
node tools/slice20-research/longrun/lr2-symmetric/run-shard.mjs --shard 2 --of 3 &
node tools/slice20-research/longrun/lr2-symmetric/summarize.mjs
```

A killed shard restarts where it stopped: it skips every body already in its NDJSON file. Spot check
without writing anything: `run-shard.mjs --only "433,99942,2000 SG344"`.

## Choices a reviewer should know about

- **Order.** Seeded shuffle (seed 2026111302) of the designation-sorted catalog; shard `i` takes shuffle
  positions `p % 3 == i`. A partial run is therefore an unbiased sample.
- **Outbound window.** The production `computeCompareData`, called with the compare page's own arguments.
  Those constants are private to `src/v2/app/compare/main.ts`; they are copied in `run-shard.mjs` with the
  line reference. Production providers (linear-scan Earth lookup) are used for this leg.
- **Assumed.** Production `departureDvFromVInf` applied to the outbound arrival |v∞| at the chosen cell.
- **Return grid.** 723 departure columns over [arrival + 8 d, arrival + 730.5 d] (about 1.0007 d apart) by
  100 TOF values over 182.5-1826.25 d, M = 0. DEC-20-2 fixes the window and the TOF range; the column
  count is this run's choice (S20_01 R3 used 1-day columns). M = 1 was not run: DEC-20-2 says M = 0 only
  where compare is involved.
- **Kernel.** The unedited `computePorkchopGrid` with swapped providers. A refused cell is handed a NaN
  Earth position and an injected `solveLambert` returns `null` for it without calling the solver; every
  other cell goes to the production `lambertMultiRev` unchanged.
- **Refusal (DEC-20-3).** Earth arrival after the last Earth sample, computed as the kernel computes it.
- **Support (DEC-20-5).** A return cell counts as unsupported when its asteroid departure is at or after
  the body's L1 encounter date (`supportBoundaryFor`). The headline `computed` ignores support; the
  supported-only minimum is stored beside it.
- **Secondary window.** Not in the dispatch. The outbound cell minimizing the production sample-return ΔV
  stack, measured the same way. S20_01 R3 measured both kinds of window and found the error changes sign
  between them; without the secondary rows the catalog-wide numbers could not be compared with the
  six-window range in DEC-20-7. Drop the `sec*` columns to get exactly what the dispatch asked for.

## Checked against S20_01 R3

`--only "433,99942,2000 SG344"` reproduces all six R3 rows at M = 0. Five match to the printed digits. The
sixth (2000 SG344, best stack) gives 0.2427 km/s against R3's 0.2244: R3's return window started at
arrival, this one starts 8 days later, as DEC-20-2 requires.
