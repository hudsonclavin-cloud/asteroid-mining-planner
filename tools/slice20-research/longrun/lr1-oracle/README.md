# LR1 — K1 return-leg oracle dataset

LEADS-grade research evidence from the S20_LONGRUN dispatch (Nova, 2026-11-13). Not a validation; no
pass/fail threshold is set. Nothing here enters a DEC, a test or the site.

**Where it ran:** a cloud Linux container, not the laptop the dispatch names. Hudson waived tripwire (a)
in-session on 2026-11-14 and authorized creating the poliastro venv there. Node v22.23.4 (the laptop
runs Node 24). Oracle venv: Python 3.12.3, poliastro 0.17.0, astropy 5.3.4, numpy 1.26.4, scipy 1.17.1,
numba 0.68.1 — the same pins S20_01 R6 records for the laptop venv, except the Python patch version
(3.12.10 there). poliastro 0.17.0 declares `Requires-Python <3.11`, so it was installed with
`--ignore-requires-python`.

## What is in this folder

| File | What |
|---|---|
| `build-cells.mjs` | Step 1+2. Seeded body and cell sample; solves each cell with the unedited `computePorkchopGrid` and swapped providers; recomputes the v-infinity vectors. Writes scratch only. |
| `oracle_driver.py` | Step 3. New poliastro driver (not the Slice 11 one). Reads and writes only the two paths given on its command line. |
| `report.mjs` | Step 4. Merges, computes deltas, writes the dataset, `lr1-summary.json` and `REPORT.md`. |
| `lr1-oracle.part1of1.json.gz` | The dataset: one record per converged branch with inputs, both v-infinity vectors (Aster and oracle) and deltas. **Gzipped** because the raw JSON is about 30 MB and the dispatch caps committed files at 10 MB. |
| `lr1-summary.json` | Every aggregate in the report, uncompressed. |
| `REPORT.md` | Generated by `report.mjs`; no number in it is typed by hand. |

## Reproduce

```bash
export LONGRUN_SCRATCH=<a directory outside the repo>
node tools/slice20-research/longrun/lib/build.mjs
node tools/slice20-research/longrun/lr1-oracle/build-cells.mjs
<venv>/bin/python -I tools/slice20-research/longrun/lr1-oracle/oracle_driver.py \
  "$LONGRUN_SCRATCH/lr1/lr1-cells.json" "$LONGRUN_SCRATCH/lr1/oracle-results.json"
node tools/slice20-research/longrun/lr1-oracle/report.mjs
```

On Windows the interpreter is `%USERPROFILE%\.aster-slice11-venv\Scripts\python.exe`; nothing in the
driver is POSIX-specific. The production TypeScript is compiled with the repo's own tsc into
`$LONGRUN_SCRATCH/build-v2`, never into the worktree.

## Method notes a reviewer needs

- **Kernel:** the unedited `computePorkchopGrid` on a 1x1 grid per cell, so the sampled epochs are the
  same floats a full 731x100 grid would use. Provider swap as DEC-20-1 describes.
- **Refusal (DEC-20-3):** a cell is refused when its Earth-arrival epoch, computed exactly as the kernel
  computes it, is after the last Earth sample. Refused cells are counted, never solved.
- **Sample:** 40 bodies, 4 L0 / 18 L1 / 18 L2 (L0 has only 11 bodies; one of them, 2015 D1, is not
  propagatable and was skipped). 150 cells per body: the admissible cells in departure-major order are
  cut into 150 contiguous chunks, one seeded draw per chunk.
- **Branch mapping for M=1** is fixed from the two codebases before any comparison (right = lowpath
  True, left = lowpath False). The other mapping is stored as a diagnostic.
- **vallado's `prograde` flag** in poliastro 0.17.0 selects the short way, not the direction of motion.
  The driver derives it from `(r1 x r2).z`.
- **Closure** uses two poliastro propagators (analytic `farnocchia_rv`, numerical `cowell`). Their own
  disagreement is stored, because on near-rectilinear transfer orbits it dominates the miss distance.

## Not done here

- M=2 was not sampled (the dispatch asks for M=0 and M=1; DEC-20-9 names M=0, 1, 2).
- No tolerance is proposed for DEC-20-9(c). REPORT.md shows why one number would not fit all cells.
